## Practice analysis follow-up (candidate build 34, not publicly released)

- Added an authenticated Netlify transcription route, one-time explicit consent, server-derived actor/access checks, a shared atomic 12/hour account quota, bounded audio/text/duration and supported-container checks. The provider receives audio only, without expected lyrics; text alignment runs separately. Provider diagnostics reject silent/uncertain/repetitive segments rather than inventing a vocal score. The diagnostic thresholds follow OpenAI Whisper's reference transcription implementation: https://github.com/openai/whisper/blob/main/whisper/transcribe.py . This conservative filter still needs validation on real singing.
- Native file transcription uses the installed Apple Speech / Android Speech APIs, not Apple Foundation Models or Gemini Nano. Android saved-file recognition requires API 33+ and an installed offline language model. Unsupported devices offer an explicit cloud choice, never an automatic fallback.
- Patched expo-speech-recognition 56.0.1: iOS previously advertised every supported locale as installed, and could silently omit requiresOnDeviceRecognition for unsupported languages. The patch filters locales with per-locale on-device capability and rejects an unsupported offline request before starting. Offline requests need only the microphone permission, avoiding an unnecessary network-speech permission prompt.
- Native recognition lifecycle tests cover final-only results, silence/partial-only results, timeout, permission rejection, concurrent starts, cancellation, late events and clean retry. No recognition failure deletes the take.
- Lyric matching uses bounded Unicode-aware word error alignment, including Nordic languages and omitted/repeated/different words. Neither pronunciation nor musical timing is inferred from text. Generic practice tips remain explicitly labelled. The legacy Express adapter also stops generating acoustic scores from word counts.
- Session metadata is saved before optional network analysis. Result persistence now occurs outside React state updaters and completes before showing success. Local audio files remain separate from cloud analysis and sharing.
- Found and fixed the Android image-picker config's microphonePermission:false removing RECORD_AUDIO from the final merged permissions. Expo introspection now includes it. APK 5 must not be distributed; a newly compiled APK and native recording checks are still required.
- Current checks: 141 unit tests passed; TypeScript and scoped ESLint passed. Five new browser UI tests passed for explicit consent, unchanged automatic-cloud preference, saved results in a second page, 422/429/503 retry, cancellation/late result, duplicate submission and 320px layout. These use isolated fixtures and are not evidence of successful provider/native integration.
- A real provider request with newly generated synthetic speech was rejected with HTTP 429 / credit_balance_exhausted. The server-only provider secret is configured, but usable provider credit is a remaining E2E gate. No real user recording was submitted for that test. The public release remains held.

A local Hugging Face/Transformers.js prototype (CPU, q8, cached models on the external test disk) was tested using newly generated English/Norwegian speech and an 8-second digital-silence WAV. These small models do not meet the Norwegian quality gate; no Hugging Face service is deployed.

### Wrong take selected — 22 October, candidate 36

The owner supplied physical-iPhone screenshots showing a completed on-device comparison, with no shared words. The recogniser returned unrelated text. The owner then clarified that the app was selecting an older recording instead of the newly recorded take. Those screenshots prove that recognition returned a result, but do not certify transcription of the intended new recording.

Source inspection identified a concrete audio-identity defect: on iOS, Expo Audio's prepare call without options can reuse the existing AVAudioRecorder and cache URL. Our durable-copy migration then reused the first file with that basename. A later take could therefore open/analyse the first preserved copy. New recording preparation now passes explicit options to create a fresh native recorder/file, and each new take is copied to a separate take-ID path. A destination collision never selects an existing older copy. Existing library migration remains idempotent; no old audio is overwritten or retrospectively relabelled as a new take. Already misassociated historical takes cannot be reconstructed reliably from their metadata alone.

A regression test changes the source bytes under a reused cache filename and verifies two distinct durable contents, preservation of the first take and the older migrated file, and safe handling of an identity collision. A browser test records two successive takes in the same screen lifecycle, checks that each opens its own session ID/audio URI, and verifies that each analysis request contains exactly that saved take's bytes. The requests use isolated fixtures; this is not a speech-provider accuracy test.

The updated iOS Release simulator recorded two successive takes of 33 and 97 seconds without restarting the app between them. Actual document files had different names, sizes and SHA-256 digests. After the second save, both the first take and the pre-existing 19-second library recording were byte-for-byte unchanged. Session Review opened the second take with a 1:37 player duration and playback advanced to 0:52. Evidence: identity-ios-after-first.json, identity-ios-after-second.json and identity-ios-latest-playback.png in local outputs.

No-shared-word results now display “No word matches” with neutral styling and the recognised text immediately visible, rather than a red 0% that can look like a vocal score. They do not produce targeted word-practice hints, including for older stored results. The underlying alignment/counts remain available. This does not hide imperfect matches, invent acoustic confidence, or validate pronunciation/timing.

Checks: 148 unit tests passed, TypeScript and scoped ESLint passed; 16 affected analysis/layout/access/recording browser cases plus the new successive-take case passed. The 320px no-match result was visually inspected. Physical-iPhone testing must use a newly recorded take after installing candidate 36; build 35 still contains the audio-identity defect. Public-store release remains held.

Source fix pushed as 7254ef0. Apple processed build 36 as VALID (delivery f11cb3c4-4c85-4683-82f8-93c89197ac45); the existing internal TestFlight group contains it.
