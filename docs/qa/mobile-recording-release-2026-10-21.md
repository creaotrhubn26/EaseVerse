# EaseVerse mobile recording release QA — 21 October 2026

Apple accepted processing of 1.0.0 (33), delivery 3c7d1448-d4fd-47bd-b694-67c55936c9d6. Its source was 0108fc9, before the follow-up fixes below. It is internally available, not submitted to public App Review. The tester confirmed opening it on a physical iPhone and that recording works. Other physical-device behavior is not yet certified.

## Follow-up fixes

- Session Review's three narrow statistic cards broke status words mid-word on iPhone. Responsive labelled rows preserve complete words. Three browser cases check every word's bounds at 320, 390 and 768 px and keyboard operation of the tips disclosure. The date row wraps naturally.
- The microphone rationale now scrolls on short/large-text screens and its full-width permission button has padding, a minimum touch height and dark text against orange.
- Generic genre coaching is labelled as general practice tips, explicitly separate from assessment of this recording, and collapsed by default.
- Native recordings previously stayed in purgeable ExpoAudio cache and stored absolute iOS sandbox paths. An app reinstall relocated the container, making an existing 19-second take unavailable. Native startup now rebases known document/cache paths and copies recovered recordings into Documents/easeverse-recordings. New recordings are preserved there when stopped. Missing files remain unavailable; failed copies retain the source and retry later. No audio is uploaded by migration.
- The existing test take was recovered after reinstall in the Release simulator and playback reached 0:18/0:18. Its 280,561-byte durable copy was verified locally. Six unit cases cover sandbox relocation, document relocation, full disk, missing files, traversal/remote URLs and Android paths.
- Patch-compatible proxy-addr and shell-quote updates remove the two critical findings identified by npm audit. Other dependency findings require separate assessment; this is not a claim of a clean dependency audit.

The emulator has audio I/O disabled, so it cannot certify audible playback or physical microphone quality. A Google Play-delivered build and pre-launch report are separate gates.

Generic text-derived heuristics do not establish phonetic pronunciation or musical timing. This must not be marketed as validated vocal assessment. Public-store submission remains held for native E2E, reviewer access, privacy/deletion requirements and store declarations.

## Practice analysis follow-up (candidate build 34, not publicly released)

- Added an authenticated Netlify transcription route, one-time explicit consent, server-derived actor/access checks, a shared atomic 12/hour account quota, bounded audio/text/duration and supported-container checks. The provider receives audio only, without expected lyrics; text alignment runs separately. Provider diagnostics reject silent/uncertain/repetitive segments rather than inventing a vocal score. The diagnostic thresholds follow OpenAI Whisper's reference transcription implementation: https://github.com/openai/whisper/blob/main/whisper/transcribe.py . This conservative filter still needs validation on real singing.
- Native file transcription uses the installed Apple Speech / Android Speech APIs, not Apple Foundation Models or Gemini Nano. Android saved-file recognition requires API 33+ and an installed offline language model. Unsupported devices offer an explicit cloud choice, never an automatic fallback.
- Patched expo-speech-recognition 56.0.1: iOS previously advertised every supported locale as installed, and could silently omit requiresOnDeviceRecognition for unsupported languages. The patch filters locales with per-locale on-device capability and rejects an unsupported offline request before starting. Offline requests need only the microphone permission, avoiding an unnecessary network-speech permission prompt.
- Native recognition lifecycle tests cover final-only results, silence/partial-only results, timeout, permission rejection, concurrent starts, cancellation, late events and clean retry. No recognition failure deletes the take.
- Lyric matching uses bounded Unicode-aware word error alignment, including Nordic languages and omitted/repeated/different words. Neither pronunciation nor musical timing is inferred from text. Generic practice tips remain explicitly labelled. The legacy Express adapter also stops generating acoustic scores from word counts.
- Session metadata is saved before optional network analysis. Result persistence now occurs outside React state updaters and completes before showing success. Local audio files remain separate from cloud analysis and sharing.
- Found and fixed the Android image-picker config's microphonePermission:false removing RECORD_AUDIO from the final merged permissions. Expo introspection now includes it. APK 5 must not be distributed; a newly compiled APK and native recording checks are still required.
- Current checks: 141 unit tests passed; TypeScript and scoped ESLint passed. Five new browser UI tests passed for explicit consent, unchanged automatic-cloud preference, saved results in a second page, 422/429/503 retry, cancellation/late result, duplicate submission and 320px layout. These use isolated fixtures and are not evidence of successful provider/native integration.
- A real provider request with newly generated synthetic speech was rejected with HTTP 429 / credit_balance_exhausted. The server-only provider secret is configured, but usable provider credit is a remaining E2E gate. No real user recording was submitted for that test. The public release remains held.

### Follow-up error visibility and Hugging Face investigation

The owner reported that tapping native analysis appeared to do nothing. Native navigation and playback seeking still worked. The Release simulator reproduced an immediate recognition error whose message was below the fold. Candidate 35 moves the error directly below the analysis heading and now visibly reports the failure, with the original take retained. This fixes failure visibility, not recognition success. Preparation waits are also cancellable and bounded so a hung native state/permission/model call cannot hold the retry lock forever. The current simulator cannot yet certify a successful native transcription.

A local Hugging Face/Transformers.js prototype (CPU, q8, cached models on the external test disk) was tested using newly generated English/Norwegian speech and an 8-second digital-silence WAV. No paid API or user recording was used. whisper-base matched 11/11 English words but 3/7 Norwegian; whisper-small matched 11/11 English but 4/7 Norwegian. Raw recognition hallucinated text on digital silence. An explicit finite-sample/near-silence signal check now prevents that silent input reaching the recogniser; both prototypes then rejected digital silence. This is not a speech/music classifier and does not validate recognition over instrumental music or real singing. These small models do not meet the Norwegian quality gate; no Hugging Face service is deployed.

After the follow-up, 145 unit tests and TypeScript/scoped ESLint passed, and the five affected analysis browser cases passed again. Apple build 34 upload succeeded as delivery 4a37381c-a6d9-455d-8ce9-fcfce2a602d5. Build 35 remains a local simulator candidate. Android AAB 6 is built; preview APK 6 is in the remote queue. Excluding generated ios-build products reduced EAS source upload from 640 MB to 96.6 MB without excluding app source or native dependency patches.

### Native package and model comparison results

Apple processed build 35 as VALID, delivery 625b4614-6274-4055-94e1-c5c1f6402ef6, and the internal beta group contains it. The owner has been asked to test local recognition on a physical iPhone. No public App Review submission occurred.

The actual production AAB 6 manifest was inspected with Google's bundletool 1.18.3: target API 36, versionCode 6 and RECORD_AUDIO present. A universal APK was generated from that AAB with a separate ephemeral QA debug signing key and installed in a new isolated API 36 emulator (5558), preserving the previous emulator apps. Maestro confirmed recording, stop/save, Session Review, playback advancing to 0:11 of 1:49 and reopening the saved take after process restart. An immediate post-launch tab tap initially missed navigation; a settled-app retry reopened the saved take. This is not Google Play signature, audible-output or physical-microphone certification: emulator audio I/O is disabled. The EAS preview APK is a duplicate build; the AAB itself was used for these checks.

The stronger local Hugging Face model onnx-community/whisper-large-v3-turbo matched 11/11 English and 7/7 Norwegian synthetic words and rejected digital silence after the signal gate. Its cached-model Norwegian inference took 1,579 ms on this Mac; initial model download/load made the first call take 306,882 ms. This is a promising prototype, not a singing or production-service benchmark. Architecture, comparison and outstanding acceptance gates are documented in docs/architecture/practice-analysis-huggingface.md. No paid Hugging Face service or new production compute was provisioned; the published analysis provider has not been switched.

The follow-up Android cold-start flow now waits for the hydrated song screen and its opening animation before selecting Sessions. It passed stop/start, restored library, reopening the same take, playback and pause. This resolves the test's immediate-launch tap timing; no claim is made that the first missed tap was a separately fixed application defect.
